# AlphaBuddy 金融投研评测集（app/benchmark/）

验证产品四件事：**取数正确、可追溯、合规拦截、显式降级**。思路对标财搭子团队开源的
[Fans-Pilot/financial_rag_benchmark](https://github.com/caidazi/financial_rag_benchmark)，
规模与评价方式适配"AlphaBuddy"产品形态。

## 结构

```
benchmark/
├── intents.json   # 意图体系（5 类：数值型/内容型×2/拦截型/降级型）
├── cases.jsonl    # 20 条评测用例（数值型 8 / 内容型 5 / 拦截型 4 / 降级型 3）
├── runner.py      # 评测脚本（PEP 723，uv run 直接跑；打后端 HTTP API）
├── results.json   # 最近一次基线结果（由 runner 生成）
└── README.md
```

## 对标 Fans-Pilot 的设计与裁剪

| Fans-Pilot | 本评测集 | 裁剪原因 |
|---|---|---|
| 意图分类（intents.json） | 同款：5 个意图各含说明与示例 | 保留；意图按产品能力边界划分而非按数据源 |
| 数值型查询，答案=数值+单位，Accuracy | 同款：期望值+单位，容差 ±0.05，要求值与单位同行出现 | 保留；期望值全部抄自 `backend/fixtures/` 已验证数据，不编造 |
| 内容型查询，Rouge/相似度+模型指标 | 改为：结论关键词命中率 + 证据四要素齐全率 + 必引证据字段出现率 | 本产品产物是"带证据清单的研究报告"而非自由文本，Rouge 对结构化产物不敏感；四要素齐全率直接对应产品"可追溯"卖点 |
| 查询源于真实用户日志 | 用例围绕演示主线（寒武纪 2026 中报）手工构造 | 24h 冲刺无真实日志；优先覆盖产品的合规/降级差异化能力 |
| —（无） | 合规拦截型 + 异常降级型 + 通用防编造核验 | 产品红线（不预测涨跌/不推荐买卖）与铁律（数字必须回指工具信封）是核心评分点，必须进评测 |

通用防编造核验（所有产出报告的用例）：报告中的每个数字必须能回指本次工具信封
（信封 data 数值 ±0.05、元→亿元换算、或作为子串出现在信封 JSON 的 as_of/caliber/URL 中），
否则判 FAIL。这直接验证架构铁律"产物数字由后端从信封渲染"。

## 运行

```bash
# 前提：后端已启动（fixture 模式即可）
cd app/backend && ALLOW_FIXTURE_FALLBACK=true uv run uvicorn app.main:app --port 8000

cd app/benchmark
uv run runner.py                    # 全量 20 条 → results.json + 终端表格
uv run runner.py --case num-01      # 单条调试
uv run runner.py --base-url http://<host>:8000
```

runner 对每条用例走完整产品链路：建线程 → `/run`（SSE）→ interrupt 后 approve → `/run`
→ 取报告与事件流 → 按意图类型打分，并统计每条用例的工具调用数与端到端耗时。

### 基线 v1 解读

- **取数正确 + 防编造**：数值型 8/8，全部用例的通用防编造核验通过——报告中数字 100% 可回指工具信封。
- **合规拦截**：4/4，guard warning 触发且均未进入研究计划，端到端耗时 ≈0s（不进图，零工具调用零成本）。
- **显式降级**：3/3，不存在标的 999999.SH 触发 `missing_key` 错误信封，报告明示"数据不足"且无编造数值；步骤标 failed 但任务正常走完产出报告。
- **可追溯缺口（评测发现的真实问题）**：内容型用例四要素齐全率 0.75——`ifind_announcement`
  工具信封缺 `as_of`（公告日期在 data 内部字段，未提升到信封层）。

## 基线 v3（2026-09-24，真实数据源：扶摇 + iFinD MCP + DeepSeek deepseek-flash，fixture 兜底开启）

| 意图 | 用例数 | Accuracy | 通过率 | 工具调用 | 总耗时(s) |
|---|---|---|---|---|---|
| 个股数据查询（stock_data_query） | 8 | 1.000 | 100% | 32 | 88.67 |
| 命题验证（thesis_validation） | 4 | 1.000 | 100% | 16 | 45.13 |
| 财报点评（earnings_review） | 1 | 1.000 | 100% | 4 | 11.94 |
| 合规边界（compliance_boundary） | 4 | 1.000 | 100% | 0 | 0.03 |
| 异常降级（degradation） | 3 | 1.000 | 100% | 11 | 34.06 |
| **总计** | 20 | **1.000** | **100%** | 63 | 179.83 |

### v3 说明

- **期望值零漂移**：8 条数值型用例的期望值（fixtures 2026-09-23 录制）经 2026-09-24 真实
  iFinD `get_stock_financials` 复核全部一致（容差 ±0.05 内），未改动任何期望值；
  cases.jsonl 的 `source_of_truth` 已注明复核日期。评测用例设计上不依赖行情快照/估值等
  随交易日漂移的字段。
- **iFinD 与 fixtures 对账**：营收 59.9557 亿✓、营收同比 108.1331✓、归母 23.1091 亿✓、
  归母同比 122.6135✓、扣非同比 137.3038✓、毛利率 55.2506✓、净利率 38.541✓、
  研发费用率 11.7164✓、投资收益 8327 万✓、其他收益 1.6725 亿✓、资产减值 3.9702 亿✓。
  差异两处：① fixtures 未录的扣非绝对额，真实值 21.6556 亿；② 主营占比真实计算值
  99.9922%（fixtures 录 99.9995%，亿元舍入口径差异）——均在容差内，不影响判定。
- **真实 LLM 接入后的评测驱动修复**（详见 TESTING.md / AI_LOG #6–#8）：
  ① LLM 结论曾出现证据外的算术衍生数字（0.83+1.67→"约 2.51 亿"）被防编造核验捕获，
  prompt 已禁止任何算术加工；② LLM 一度只罗列证据不给判定，命题判定句改为程序基于
  证据数字计算后前置，LLM 只写解读；内容型关键词支持 `a|b` 同义候选。
- **deg-02 抓出高危 bug**：请求 999999.SH 被 iFinD 模糊匹配成 601999.SH 出版传媒并返回
  其真实数据（静默错数据 + 污染长期记忆）。修复：normalize 校验返回证券代码与请求一致，
  不一致按标的不存在转错误信封；v3 降级型 3/3。
- **耗时**：真实模式单用例 10–31s（iFinD 指标类 query 约 6–9s，贴近 10s 单工具超时，
  偶发超时按设计降级为错误信封/fixture）；fixture 模式单用例 <0.1s，适合快速回归。

## 已知边界

- 真实数据源的 query 语义由 iFinD 自然语言引擎解释，指标集合可能随 query 措辞波动；normalize 解析失败时原文入 data 兜底，不会崩。
- 内容型评价未用模型指标（LLM-as-judge），后续可加一层语义评分作对照。
- 用例集中于单一标的单一报告期（演示主线），后续可扩充 fixtures 与真实标的池扩大覆盖面。
